# 生成式影片串接

三段生成的片直接 `concat` 起來幾乎一定不對勁。原因不在 ffmpeg，在素材：
用尾幀續生的下一段，開頭常有半秒幾乎不動的**緩啟動**。接起來就是動作走到一半停住，
再重新起步——觀眾說「卡住了」「好像重複」，但那不是幀重複，是動作斷了。

所以工作順序是**先診斷再串接**。三個腳本各管一段，都在 `scripts/`：

| 腳本 | 管什麼 |
|---|---|
| `clip_qc.py <clips...>` | 素材驗收：規格一致嗎、幀率是真的嗎、有沒有瑕疵 |
| `seam_probe.py <前> <後>` | 接縫診斷：該怎麼接、砍幾幀 |
| `join_clips.sh <A> <B> <C> <out>` | 串接 |

## 步驟 1：素材驗收

```bash
python3 scripts/clip_qc.py 01.mp4 02.mp4 03.mp4
```

先擋掉會讓後面白做工的問題。**這一步最常抓到的是預覽版混進高清版裡**——
生成平台通常同時提供兩種，檔名可能一模一樣，只有解析度和幀率不同。
拿預覽版去接，放大 3 倍後糊掉，而且補幀補不回來。發現版本不一致就回頭重下，別硬接。

腳本回報三個幀率，它們不是同一件事：

- **容器 fps** —— mp4 標頭寫的，任何人都能寫任何數字
- **幀密度** —— 幀數 ÷ 時長，容器裡真的有這麼多幀
- **有效 fps** —— 扣掉複製幀後真正在動的，這才是觀眾感受到的流暢度

三者可以差很遠。30fps 的內容硬包成 60fps 容器，前兩個都會顯示 60。

> 偵測幀率灌水不能數「diff 為 0 的幀」——複製幀重編碼後會帶進壓縮雜訊，
> diff 落在 0.02~0.15 而不是 0，任何絕對門檻都會漏報。腳本改看**相位結構**：
> 每 P 幀裡固定有幾幀沒動，這個週期性簽名壓縮殺不掉。實測灌水素材的
> 奇偶相位差是 7.5x，真素材是 1.1x，區分度極高。

**停滯幀**是另一回事：素材有一段動作特別鈍。它是單次生成的隨機瑕疵，
不是流程問題——同一批素材裡通常只有某一段中招，重生成那段就乾淨了。
超過 5% 就值得回報給使用者，讓他決定要不要重生成。

## 步驟 2：接縫診斷

對每一個接縫跑一次（三段片有兩個接縫）：

```bash
python3 scripts/seam_probe.py 02.mp4 03.mp4
```

接縫只有三種，處理方式完全不同，**弄錯會做出反效果**：

| 類型 | 簽名 | 處理 |
|---|---|---|
| **不同鏡位** | 最佳 MAE ≈ 無關配對的量級 | 硬切，不要加轉場 |
| **構圖延續** | 後段開頭停在前段末畫面上，對應位置**不移動** | 砍死水 + 短溶接 |
| **真重疊** | 對應位置隨時間**往前推移**（斜線） | 砍掉被重演的段落 |

判別的關鍵是**對應曲線**：後段的每一幀最像前段的哪一幀。
平線代表「都停在同一個畫面上」（構圖延續），斜線才代表「動作被重演」（真重疊）。
只比對單幀分不出這兩者，而它們的剪法是相反的。

腳本會印出對應曲線和一個**對照組**（任意配對的 MAE 中位數）。
對照組不是裝飾——沒有它就無從判斷「MAE 11.6」算高還算低。

### 切點怎麼定：看比值，不是看絕對值

構圖延續的情況下，唯一要決定的是砍幾幀。判準是：

**接縫後的運動量 ÷ 接縫前的運動量，要趨近 1。**

腳本會掃一遍候選值列表給你挑。低於 0.75 是死水（動作接不上），
高於 1.4 是暴衝（砍過頭，動作突然加速）。

> 這條是踩出來的。曾經只看後段自己的曲線「前低後高」就判定是緩啟動，
> 推出要砍 54 幀——實際正解是 0。錯在沒有跟前段的基準比：那一段前段結尾本來就慢，
> 後段開頭的低運動量是**匹配**的，不是死水；它後面變快是動作本身在加速，
> 不是「緩啟動結束」。同一條曲線配不同基準線，結論完全相反。
> 兩批素材（直版與橫版）看起來一模一樣，切點卻是 30 與 0，不能互相套用。

即使 CUT_FRAMES=0，仍建議留 0.1s 交叉溶接：續生的片段與前段尾幀有
材質和光影差異（MAE 通常 10～13），硬切會閃一下。構圖既然重合，溶接不會產生鬼影。

## 步驟 3：串接

```bash
CUT_FRAMES=30 scripts/join_clips.sh 01.mp4 02.mp4 03.mp4 out.mp4
```

預設 A→B 硬切、B→C 溶接，這是最常見的組合（第一個接縫多半是換鏡）。
若 `seam_probe` 判定 A→B 也是構圖延續，加 `SEAM1=xfade`。

腳本一次編碼完成，中間不落地——避免二次編碼掉畫質。
`offset` 由腳本自己從 ffprobe 讀時長算，不要手填。

### 三個 ffmpeg 地雷

會踩到是因為它們的失敗方式都不直觀：

1. **`concat` 的輸出接 `xfade` 前必須 `fps=N,settb=AVTB`**
   否則報 `Error reinitializing filters`——訊息完全不提 timebase，
   而且兩步分開跑都正常，只有串起來才死。
2. **音訊每一路都要 `aformat` 統一取樣格式**
   否則 AAC 編碼器回 `-22 Invalid argument`，看起來像編碼器壞了。
3. **`xfade` 的 `offset` 算錯不會報錯**
   ffmpeg 照樣 exit 0，只是把轉場放到錯的時間點，要播出來才發現。
   前兩個會大聲報錯（好排查），這個靜默失效——所以腳本自動算並印出來。

## 步驟 4：驗收

串完必須驗，而且**不能只看 ffprobe 的標記**：

```bash
python3 scripts/clip_qc.py out.mp4        # 有效 fps 應與素材相同
```

再加這三項：

- **時長對帳** —— 應等於「各段時長總和 − 砍掉的秒數 − 溶接秒數」，誤差在幾幀內
- **接縫定格** —— 抽接縫前後幾幀並排目視，確認溶接沒有鬼影、硬切連戲
  ```bash
  ffmpeg -i out.mp4 -vf "select=eq(n\,1738),scale=260:-2" -vsync 0 seam.png
  ```
- **音訊分段量測** —— 沿全片抽幾個點跑 `volumedetect`，確認沒有靜音段或爆音
  ```bash
  ffmpeg -hide_banner -nostats -v info -ss 28 -t 3 -i out.mp4 -af volumedetect -f null -
  ```
  注意 `volumedetect` 的輸出是 info 級，用 `-v error` 會什麼都看不到。

## 回報時說什麼

使用者要的是「接縫修好了沒」，不是 MAE 數值。先講他看得到的癥狀和處置，
再附數字當證據。務必說清楚**哪些驗過、哪些沒驗**——
定格目視和運動量曲線都不等於實際播放過一遍，那句話要老實講。

素材本身的瑕疵（停滯幀、版本不一致、兩批素材敘事進度不同）要主動點出來，
即使不影響這次串接——那是他決定要不要重生成的依據。
